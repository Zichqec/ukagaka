My code for idling between dialogues has been updated! This is code that makes your ghost change surfaces at random intervals even when not talking, and even if talking is turned completely off.

I initially wrote this code for Xander's Refuge because I wanted him to have a lively feel, and it felt particularly fitting to have him be smoking even while not doing anything else. However, I was never entirely happy with my implementation.

This is the original implementation of the code:

OnSecondChange
{
	//This gets the time since the last dialogue ended, in seconds. SHIORI3FW.TalkEndTime is a variable that comes with YAYA as SHIORI
	_since = GETSECCOUNT - SHIORI3FW.TalkEndTime
	
	//status is an inbuilt YAYA variable that has information on if the balloon is open, etc.
	_balloonisopen = "balloon" _in_ status
	
	if _since % 15 == 0 && !_balloonisopen
	{
		if RAND(4) == 0; OnSurfaceRestore
	}
}

OnSurfaceRestore : nonoverlap
{
	"\1\s[-1]\0\s[0]"
	"\1\s[-1]\0\s[1]"
	"\1\s[-1]\0\s[2]"
	"\1\s[-1]\0\s[3]"
	"\1\s[-1]\0\s[4]"
}

It's a pretty simple setup. Track how long it's been since the last dialogue occurred, and every 15 seconds, as long as the balloon is not open, try to do a random surface change. To avoid changing the surface every 15 seconds exactly, which would feel robotic, I made it only have a 1/4 chance to actually do the change.

This works, and is an overall simple and light implementation. However, two things have always irked me about it. First, even though I avoided having the surface always change every 15 seconds, the changes would still always happen at multiples of 15 seconds. You won't really notice this, but it's not as granular as I'd like. It bugs me. Second, if you get terrible RNG, the ghost can theoretically stay on the same pose for a really long time, longer than I'd want. There isn't a way to control the maximum length.

Of course, these are overall minor issues, and I think the code still serves its purpose well. In real usage you wouldn't really notice these things.

However, last Ghost Jam, I had the opportunity to write this anew. We made the ghost Thoughtful Replies, and we really wanted the character to move around and change expressions between dialogues since builds up the atmosphere of a character taking their time and pondering what to write in their letter. And since we were making the ghost with only new assets, I would need to write the idle code from scratch... which gave me a great chance to rethink it from the ground up and see if I could find a better approach.

I'm pleased to report that I did! Thoughtful Replies has an all new system that is still very light, but provides me with the control I wanted. This ghost was made in Aosora, so this Aosora version was written first.

function OnAosoraLoad
{
	TimeSinceLastTalk = Time.GetNowUnixEpoch();
	SetSurfaceRestoreRand();
}

function SetSurfaceRestoreRand
{
	SurfaceRestoreRand = Random.GetIndex(30,61); //30-90 seconds
}

function OnSecondChange
{
	//If the ghost is unable to respond, update the timestamp of when the ghost last talked
	if (Shiori.Reference[3] == 0) TimeSinceLastTalk = Time.GetNowUnixEpoch();
	
	local since = Time.GetNowUnixEpoch() - TimeSinceLastTalk;
	
	if (since >= SurfaceRestoreRand) return OnSurfaceRestore;
}

function OnSurfaceRestore
{
	TimeSinceLastTalk = Time.GetNowUnixEpoch();
	
	return Random.Select([
		"\1\s[-1]\s[0]",
		"\1\s[-1]\s[1]",
		"\1\s[-1]\s[2]",
		"\1\s[-1]\s[3]",
		"\1\s[-1]\s[4]",
	]);
}

Since I was writing this in Aosora, I had an additional hurdle, which is that Aosora doesn't have YAYA's built in SHIORI3FW.TalkEndTime variable. So, part of the code here is replicating the function of that. That's what the TimeSinceLastTalk variable is for. Thankfully, it's easy to recreate this with OnSecondChange since Reference3 in that event tells you if the ghost is currently able to send a script or not.

After that, the basic idea is that any time the ghost loads or says a dialogue, we pick a number of seconds to wait before a random surface change should happen. Then, once the ghost has stopped talking for that amount of time, we run OnSurfaceRestore to make the pose change. By doing it this way, we can set a minimum and maximum on the amount of time between surface changes, and the exact number of seconds can be anything in-between! It's much more granular that way. You could also add special logic if you wanted, such as adjusting how often the surface is changed based on the ghost's current mode.

This implementation uses epoch, since that's generally a much easier way of working with time. However, if you wanted to convert this to a SHIORI that does not have epoch, I think you could do it by just creating a seconds counter in OnSecondChange.

Note that I left out checking for whether the balloon is open in this setup. I don't think it's usually necessary to check for with this setup, but if you find that this function is interrupting balloons, then you could easily add in a check for whether the balloon is open before it runs OnSurfaceRestore.

I have also converted this code to YAYA! The version listed on my functions page is written in YAYA, since I haven't yet decided if/how I want to share snips of code from other SHIORI yet. You'll find it's overall the same, except it uses SHIORI3FW.TalkEndTime, and it uses OnInitialize instead of the Aosora-specific OnAosoraLoad.

You can of course use the old code if you prefer it or find that it suits your needs better. The functionality is slightly different, which is one of the reasons it's taken me this long to decide how to release the new version. After mulling it over a while I think it is enough of an improvement to replace the old one, rather than listing both on my function index, but I'll keep a link to this blog post so that both are available (as well as the Aosora version).

So, there you have it! One more wheel reinvented. Even though it's an overall simple function to add to a ghost, there are many different ways you could approach it, and I'm happy with the one I've settled on now.
